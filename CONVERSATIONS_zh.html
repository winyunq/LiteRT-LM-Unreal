先统一状态模型

ULiteRtLmQuickChat 不是第二套状态机。它创建并包装一个普通、缺省配置的 ULiteRtLmAgent，只负责把常用事件和操作变得更直接。

Create Quick Chat ──> default-configured Agent / Conversation ──> canonical memory A

Create Conversation (Advanced) ──> Agent B ──> canonical memory B
                               └─> Agent C ──> canonical memory C

All of them ──> one shared model + one serial GPU request queue

每次 Create Quick Chat 都会得到一条独立 Conversation，并非进程级单例。需要高级能力时调用 Get Conversation，上下文不变。

Step 0

一次性项目准备

1. 启用插件

在 Edit > Plugins 启用 LiteRT-LM-Unreal 并重启。

2. 配置模型

在 Project Settings > Plugins > LiteRT-LM 设置 Model Path。

3. 不手动 Load

创建第一个对象会自动懒加载共享模型。

4. 持有对象引用

将返回值提升为变量；不要每条消息重新创建。

Quick Start

快速单对话（Blueprint）

适用于一个聊天窗口、一个助手或一名长期 NPC。

01

创建并保存 QuickChat

BeginPlay → Create Quick Chat，填写可选 System Prompt，将 Return Value 提升为 QuickChat 变量。

02

绑定异步事件

至少绑定 On Answer 与 On Error；打字机 UI 再绑定 On Text Chunk。所有事件回到 Game Thread。

03

只选一种 Ask

Ask Once 只发最终答案；Ask Streaming 发文本块并在结尾发一次完整答案。节点返回的是 Request Id，不是答案。

04

一直复用同一个对象

下一条消息继续调用同一变量。新话题用 Reset Conversation(true)；离开用 Close；高级能力用 Get Conversation。

Ask StreamingMessage, OptionsRequest Id；块走 On Text Chunk

Multiple Conversations

多对话（Blueprint）

狼人杀的正确粒度是“一名 AI 玩家一个 Agent”。

01 · CONTAINER

创建 Agent 数组或 Map

用稳定角色 Id 找到对应 Conversation。

02 · CREATE ONCE

每个角色创建一次

Make Agent Config → Create Conversation (Advanced) → Add。

03 · EVENTS

绑定每个 Agent 的事件

通过 Agent Id、owner 或 Request Id 映射把结果路由回角色。

04 · ASK

轮到谁就 Ask 谁

Agent 忙时不重复提交；共享 GPU 队列会串行执行。

05 · MEMORY

同步事实，而不是提示词补丁

记录 3号玩家发言：“我是狼人。”；由规则层决定哪些 Agent 收到。不要追加“该信息已公开……”模板。

06 · RETIRE

结束时关闭并清空

使用 Close and Clear Conversations，阻止旧回调进入新对局。

工具动作仍由游戏规则裁决

Result.ToolCalls 只是模型提案。合法动作写入 Tool Result；非法回答准备重试时先调用 Reject Last Response，避免错误 assistant 动作留在记忆里。

Native UE API

C++ 使用相同对象模型

缺省单对话

#include "LiteRtLmBlueprintLibrary.h"
#include "LiteRtLmQuickChat.h"

UPROPERTY(Transient)
TObjectPtr<ULiteRtLmQuickChat> QuickChat;

QuickChat = ULiteRtLmBlueprintLibrary::CreateQuickChat(
    this, TEXT("Remember this conversation."));

const FString RequestId =
    QuickChat->AskStreaming(TEXT("Hello"));

多个独立 Conversation

#include "LiteRtLmSubsystem.h"

UPROPERTY(Transient)
TArray<TObjectPtr<ULiteRtLmAgent>> Conversations;

auto* Runtime = GEngine->
    GetEngineSubsystem<ULiteRtLmSubsystem>();

auto* Agent = Runtime->CreateAgent(
    TEXT("Seat 3"), TEXT("Follow your role."));

Conversations.Add(Agent);
Agent->Ask(TEXT("Give your analysis."));

Blueprint 保持唯一、无歧义的反射签名；C++ 提供省略 Options 等常用参数的重载。它们最终调用同一实现。

Memory Debugging

“AI 像没看上下文”检查表

  1. 是否每条消息都重新创建了 QuickChat/Agent？
  2. 多个角色是否错误共用了同一个 Agent？
  3. 角色知道的真实事件是否写进其 Agent，而不是只显示在 UI？
  4. Ask 是否返回非空 Request Id？
  5. 是否在 Agent 忙碌时再次提交或修改记忆？
  6. 用 Export Conversation Json / Export Memory Json 查看下一次推理前的完整历史。
  7. 规则层拒绝答案后是否调用了 Reject Last Response？

当前 Win64 GPU 运行时下，同一 Agent 连续请求可复用当前常驻 KV；切换 Agent 时从目标 Agent 的完整规范历史重建。语义不会丢失，但跨 Agent 切换可能增加 prefill。
