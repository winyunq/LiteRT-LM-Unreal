Blueprint · Beginner · 10–15 minutes

Build one local AI conversation

This tutorial creates a Quick Chat object once, keeps its reference, receives the final answer through an event, and sends more messages through the same conversation.

What you will build

At the end, pressing Play creates one conversation. A test message is queued, and the answer is printed. You can then replace the test message with your UMG input without changing the conversation setup.

Quick Chat is the default single-conversation API. It wraps one normal ULiteRtLmAgent. Every call to Create Quick Chat creates a new independent conversation, so create it once for each chat you intend to keep.
  • A valid .litertlm model is available.
  • The plugin is enabled for the project.
  • You can create an Actor Blueprint or use an existing gameplay Blueprint.

The return value of Ask is a request ID, not the model answer. Answers are asynchronous. Always read them from the event.

1. Enable LiteRT-LM

1

Open the Plugins window

In Unreal Editor, open Edit → Plugins, search for LiteRT-LM, enable it, and restart the editor when prompted.

If the plugin does not appear, verify that the plugin directory is inside your project’s Plugins folder or installed through Fab for this engine installation.

2. Point the plugin to a model

2

Set Model Path

Open Edit → Project Settings. Search for LiteRT-LM, then set Model Path to the .litertlm model that will be available at runtime.

No Load Model node is required. The first conversation triggers lazy model initialization. Use Get LiteRT-LM Runtime when you need readiness, status, or diagnostics in a loading screen.

3. Create a Blueprint that owns the conversation

3

Create or open an Actor Blueprint

For the first test, create an Actor Blueprint named BP_LocalChat and place one instance in the level. The same setup can later live in a Player Controller, Game Instance subsystem wrapper, widget owner, or any long-lived gameplay object.

4

Add the QuickChat variable

Add a variable named QuickChat. Set its type to Lite Rt Lm Quick Chat Object Reference. This reference is what preserves memory between questions.

Do not create Quick Chat inside every Send button click. That creates a fresh Agent each time, so every question starts with empty conversation memory.

4. Build the complete BeginPlay graph

5

Create and store the conversation

From Event BeginPlay, add Create Quick Chat. Enter a short system prompt, such as “Answer concisely in the user’s language.” Connect the return value to Set QuickChat.

6

Bind the answer before the first Ask

Drag from the stored QuickChat reference and add Bind Event to On Answer (or assign the On Answer dispatcher). Create the matching custom event. Break the Lite Rt Lm Result, then connect Text to Print String.

7

Queue a test question

After the binding node, call Ask Once on the same QuickChat reference. Use a small first message, compile, save, and press Play.

Model initialization can make the first request slower than later requests. Once On Answer fires, the same QuickChat object already contains the user message and assistant answer in its memory.

5. Send later messages from your UI

Keep the BeginPlay setup exactly as it is. In your UMG button handler:

  1. Read the text box value.
  2. Check that QuickChat is valid and Is Busy is false.
  3. Call Ask Once on the stored QuickChat reference.
  4. Disable Send while busy; enable it again from On Answer or On Error.
  5. Display Result.Text from On Answer.
Memory test: ask “My codename is Aurora.” Then ask “What is my codename?” through the same object. If it forgets, inspect whether your UI is creating or resetting QuickChat between the two calls.

6. Switch to streaming output

Replace Ask Once with Ask Streaming and bind On Text Chunk during setup.

  • Clear the answer label immediately before calling Ask Streaming.
  • Append each Text Chunk to the label. Do not replace the full label with only the newest chunk.
  • Use On Answer for the final result, metrics, tool calls, and terminal UI state.
  • Use On Error to restore the Send button and show a useful error.
