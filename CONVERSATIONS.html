One state model

ULiteRtLmQuickChat is not a second state machine. It creates and wraps an ordinary, default-configured ULiteRtLmAgent, exposing the common operations directly.

Create Quick Chat ──> default-configured Agent / Conversation ──> canonical memory A

Create Conversation (Advanced) ──> Agent B ──> canonical memory B
                               └─> Agent C ──> canonical memory C

All of them ──> one shared model + one serial GPU request queue

Every Create Quick Chat call creates an independent Conversation, not a process-wide singleton. Get Conversation exposes the same Agent when you need advanced APIs.

Step 0

One-time project setup

1. Enable the plugin

Enable LiteRT-LM-Unreal under Edit > Plugins, then restart.

2. Configure the model

Set Model Path under Project Settings > Plugins > LiteRT-LM.

3. Do not load manually

The first created object starts lazy loading of the shared model.

4. Retain the object

Promote the return value to a variable; never recreate it per message.

Quick Start

Quick single conversation (Blueprint)

For one chat window, one assistant, or one long-lived NPC.

01

Create and retain QuickChat

BeginPlay → Create Quick Chat, enter an optional System Prompt, and promote Return Value to a QuickChat variable.

02

Bind asynchronous events

Bind at least On Answer and On Error. Bind On Text Chunk for a typewriter UI. Events return to the Game Thread.

03

Choose exactly one Ask mode

Ask Once emits only the final answer. Ask Streaming emits chunks and one final answer. The node returns a Request Id, not the answer.

04

Reuse the same object

Send later messages to the same variable. Use Reset Conversation(true) for a new topic, Close when leaving, and Get Conversation for advanced APIs.

Multiple Conversations

Multiple conversations (Blueprint)

The correct Werewolf granularity is one Agent per AI player.

01 · CONTAINER

Create an Agent array or map

Use a stable character ID to find its Conversation.

02 · CREATE ONCE

Create once per character

Make Agent Config → Create Conversation (Advanced) → Add.

03 · EVENTS

Bind every Agent's events

Route results by Agent Id, owner, or your Request Id map.

04 · ASK

Ask whoever owns the turn

Do not resubmit while busy; the shared GPU queue serializes work.

05 · MEMORY

Synchronize facts, not prompt patches

Record Seat 3 said: “I am a werewolf.” Game rules choose recipients. Do not append “this is public...” boilerplate.

06 · RETIRE

Close and clear at the end

Use Close and Clear Conversations so old callbacks cannot enter a new match.

Game rules still validate tool actions

Result.ToolCalls is a model proposal. Record valid actions with a Tool Result. Before retrying an invalid answer, call Reject Last Response so it cannot become a bad example in memory.

Native UE API

C++ uses the same object model

Default single conversation

#include "LiteRtLmBlueprintLibrary.h"
#include "LiteRtLmQuickChat.h"

UPROPERTY(Transient)
TObjectPtr<ULiteRtLmQuickChat> QuickChat;

QuickChat = ULiteRtLmBlueprintLibrary::CreateQuickChat(
    this, TEXT("Remember this conversation."));

const FString RequestId =
    QuickChat->AskStreaming(TEXT("Hello"));

Independent Conversations

#include "LiteRtLmSubsystem.h"

UPROPERTY(Transient)
TArray<TObjectPtr<ULiteRtLmAgent>> Conversations;

auto* Runtime = GEngine->
    GetEngineSubsystem<ULiteRtLmSubsystem>();

auto* Agent = Runtime->CreateAgent(
    TEXT("Seat 3"), TEXT("Follow your role."));

Conversations.Add(Agent);
Agent->Ask(TEXT("Give your analysis."));

Blueprint keeps one unambiguous reflected signature. C++ adds overloads that omit common parameters such as Options. Both call the same implementation.

Memory Debugging

“The AI ignored context” checklist

  1. Was QuickChat/Agent recreated for every message?
  2. Are multiple characters incorrectly sharing one Agent?
  3. Was each fact visible to this character written to its Agent, rather than only displayed in UI?
  4. Did Ask return a non-empty Request Id?
  5. Was memory changed or another request submitted while the Agent was busy?
  6. Inspect the next request's complete history with Export Conversation Json / Export Memory Json.
  7. After game rules rejected an answer, was Reject Last Response called?

On the current Win64 GPU runtime, consecutive requests to the same Agent can reuse resident KV. Switching Agents rebuilds the target Agent from its complete canonical history. Semantics are preserved, while a switch may add prefill cost.
