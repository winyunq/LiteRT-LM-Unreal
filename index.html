Local LLM · Blueprint + C++ · Win64 + Android

Start with one chat. Grow into a world of independent AI characters.

LiteRT-LM Unreal is a scenario-oriented local AI plugin. You can begin with a single automatic conversation, then move to independent Agents, memory, tools, MCP routing, native C++, diagnostics, and shipping—without rebuilding the same runtime layer.

Build your first chat Choose the right API
The mental model: the plugin owns one process-wide GPU model and a serial inference queue. Each Quick Chat or Agent owns an independent conversation and memory. “Single conversation” is a convenience facade—not a global singleton.

Choose by what you are building

You should not have to read the whole API first

Pick the object whose lifetime matches your gameplay object. The tutorials introduce the smallest useful surface first; advanced controls stay available underneath.

1

One chat box or assistant

Use Quick Chat

It creates and owns one normal Agent automatically. Bind the answer event once, then call Ask Once or Ask Streaming.
N

NPCs, players, or roles

Use one Agent per role

Prompts, tools, and memory stay independent. The runtime and model are shared, so you do not load one model per character.
A

AI belongs to an Actor

Use LiteRT-LM Component

The component creates one Agent at BeginPlay and exposes conversation, memory, and tool events on the owning Actor.
M

External tools or MCP routes

Use MCP Gateway

Use a fixed tool schema, route calls to external systems, submit results, and continue the same conversation.
C++

Gameplay or plugin code

Use UObject APIs first

Use the same Quick Chat, Agent, runtime, and gateway objects from C++. Drop to the native SDK only when you need the lower-level ABI.
→

Ship to Win64 or Android

Use model + diagnostics + packaging

Decide how the model arrives, verify the configured path, then test runtime status and diagnostics on the target device.

Recommended order

A human learning path

15 minutes

1. Make one answer appear

Set the model path, create Quick Chat once, bind On Answer, and print the final text.

Next

2. Put it behind your UI

Send from a button, keep the object reference, choose streaming or final-only output, and handle busy/error states.

Gameplay

3. Split characters

Create an Agent for each role. Route private knowledge to selected Agents and real public events to everyone’s memory.

Production

4. Add tools and shipping

Use structured tool calls, MCP if needed, diagnostics, model delivery, and target-device packaging tests.
