Conversation 对话体系

入门外观

Quick Chat

Create Quick Chat 自动创建一个底层 Agent。使用 Ask Once 或 Ask Streaming，绑定 On Answer，并让对象保持存活。以后可通过 Get Conversation 取得 Agent。

记忆、纠错与工具

Memory API

Agent 保存规范化 JSON 消息记忆，支持追加、替换、删除、清空、导入/导出、消息数量、命名存档/读取，以及 Reject Last Response。当记忆修改会与未完成请求冲突时，操作会被拒绝。

Tools API

在 ToolDeclarationsJson 中声明 OpenAI 兼容工具。模型在最终 Result 中返回结构化 Tool Calls；游戏代码负责校验和执行。模型需要看到执行结果并继续时使用 Submit Tool Result；玩法代码立即消费动作、不需要继续推理时使用 Append Tool Result to Memory。

小型辅助接口

Try Get Tool String Argument 与 Try Get Tool Integer Argument 从工具调用 Arguments JSON 中读取校验后的字段。Precise 与 Reasoned Decision 选项工厂可以避免反复手工配置采样参数。

MCP Gateway 体系

当模型可见工具需要被路由到外部 MCP 时，使用 Create MCP Gateway。Gateway 持有一个底层 Agent，通过 On Tool Call 发布调用，再由你的网络/玩法子系统执行传输并调用 Submit MCP Result。

变化API对对话的影响
把工具改路由到其他服务器Set Tool Route、Set Default Server Route路由可热切换；模型历史/KV 保留。
移除路由Remove Tool Route只改变路由注册表。
改变模型可见工具结构Rebuild Tool Schema重建 Native Conversation 并回放规范化历史；仍有 Pending Call 时拒绝。
传输层已经取消外部工作Discard Pending Tool Calls只忘记待处理派发，不会替你取消远端服务器。

Actor Component 体系

当对话天然属于某个 Actor 时，添加 LiteRT-LM Component。在 Details 中配置 AgentConfig；BeginPlay 创建一个 Agent，组件事件转发 Agent 事件，EndPlay 关闭对话。

适合：会说话的 NPC Actor、伙伴、可交互终端，或需要携带自己 Prompt 和记忆的可复用 Actor 类。如果角色只是数据且不对应 Actor，则更适合“管理器 + Agent 数组”。

Runtime、项目设置与诊断

ULiteRtLmSubsystem 是 Engine Subsystem，负责进程共享模型、队列、所有活动 Agent 和 Runtime Status。蓝图通过 Get LiteRT-LM Runtime 取得它。

区域控制/读取内容什么时候关注

模型如何到达用户设备

模型必须真实存在于最终 Runtime 解析到的路径。产品应明确选择一种策略：

  • 随产品交付：把模型加入 Staged Non-Asset 目录，并配置打包后仍能解析的路径。
  • 首次运行下载：使用异步 Download LiteRT-LM Model 节点（或 Gemma 4 E2B 便利节点），有哈希时完成校验，再持久化结果路径。
  • 仅开发机本地模型：适合编辑器迭代，但不能假定另一台电脑或 Android 设备存在同样的绝对路径。

发布到 Win64 与 Android

插件声明支持 Win64 与 Android。编辑器测试成功不等于目标设备测试成功。发布前：

  1. 确认平台二进制与模型都进入 Staged Build。
  2. 记录最终 Model Path 和 Runtime Status。
  3. 在打开大型玩法关卡前先运行一次最小 Quick Chat 请求。
  4. Android 启动闪退时同时采集 Logcat 和插件 Diagnostics Path；没有设备日志前不要直接判断成“爆显存”。
  5. 测试首次加载内存、Cancel、切后台/恢复，以及同一对话中的第二次请求。
