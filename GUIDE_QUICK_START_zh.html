蓝图 · 入门 · 10–15 分钟

做出第一段本地 AI 对话

本教程只创建一次 Quick Chat，保存对象引用，通过事件拿到最终回答，并让后续问题继续使用同一段对话记忆。

最终会做出什么

完成后，按下 Play 会创建一段对话，发送一条测试消息，并把回答打印出来。随后你只需把测试消息替换成 UMG 输入框内容，不必重做对话初始化。

Quick Chat 就是缺省单对话接口。它内部包装了一个普通 ULiteRtLmAgent。每次调用 Create Quick Chat 都会创建一段新的独立对话，所以每个需要保留的聊天对象只创建一次。
  • 已经准备好可用的 .litertlm 模型。
  • 插件已经为当前项目启用。
  • 可以创建 Actor 蓝图，或已有一个长期存在的玩法蓝图。

先决定用户应该怎样看到回答

想要的效果调用从哪里读取输出
整段回答完成后一次显示Ask OnceOn Answer → Result.Text
边生成边显示Ask Streaming累加 On Text Chunk；以 On Answer 作为最终完成事件
Ask 的返回值是 Request ID，不是模型回答。推理是异步的，真正的回答必须从事件读取。

1. 启用 LiteRT-LM

1

打开插件窗口

在 Unreal Editor 中打开编辑 → 插件，搜索 LiteRT-LM，启用插件；编辑器要求时完成重启。

如果搜索不到插件，检查它是否位于项目的 Plugins 目录，或是否已通过 Fab 安装到当前引擎版本。

2. 让插件找到模型

2

填写 Model Path

打开编辑 → 项目设置，搜索 LiteRT-LM，把 Model Path 指向运行时确实能够访问的 .litertlm 模型。

不需要 Load Model 节点。创建第一段对话时会自动触发延迟初始化。如果加载界面需要显示就绪状态、错误或诊断路径，使用 Get LiteRT-LM Runtime。

3. 创建一个负责持有对话的蓝图

3

创建或打开 Actor 蓝图

第一次测试可以创建名为 BP_LocalChat 的 Actor 蓝图，并在关卡里放置一个实例。之后同样的结构也可以放在 Player Controller、你的 Game Instance 封装、Widget 的持有者或其他长期存在对象中。

4

增加 QuickChat 变量

创建名为 QuickChat 的变量，类型选择 Lite Rt Lm Quick Chat Object Reference。这个引用就是多轮问题之间能够保留记忆的关键。

不要在每次点击“发送”时 Create Quick Chat。那会每次都创建新的 Agent，问题自然会像没有上下文一样从空记忆开始。

4. 搭出完整的 BeginPlay 节点链

5

创建并保存对话

从 Event BeginPlay 添加 Create Quick Chat。填写一句简短的 System Prompt，例如“使用用户的语言简洁回答”。把 Return Value 接到 Set QuickChat。

6

第一次 Ask 之前先绑定回答

从保存后的 QuickChat 引用拉出 Bind Event to On Answer（或对 On Answer 分发器使用 Assign）。创建对应自定义事件，Break Lite Rt Lm Result，再把 Text 接到 Print String。

7

发送一条测试问题

在绑定节点之后，对同一个 QuickChat 调用 Ask Once。先写一条短消息，编译、保存，然后按 Play。

第一次请求还要初始化模型，通常会比后续请求慢。On Answer 触发后，同一个 QuickChat 的记忆中已经包含这条用户消息和 AI 回答。

5. 让自己的 UI 发送后续消息

BeginPlay 的初始化保持不动。在 UMG 的发送按钮事件里：

  1. 读取输入框文字。
  2. 确认 QuickChat 有效，并且 Is Busy 为 false。
  3. 对已保存的 QuickChat 调用 Ask Once。
  4. 忙碌期间禁用发送按钮；在 On Answer 或 On Error 中恢复。
  5. 把 On Answer → Result.Text 写入聊天 UI。
记忆验证：先问“我的代号是极光”，再通过同一个对象问“我的代号是什么”。如果忘了，优先检查 UI 是否在两次调用之间重新创建、Reset 或 Close 了 QuickChat。

6. 改成流式输出

把 Ask Once 换成 Ask Streaming，并在初始化时绑定 On Text Chunk。

  • 调用 Ask Streaming 前清空“本次回答”的显示文本。
  • 把每个 Text Chunk 追加到现有文本；不要只用最新 Chunk 覆盖整段回答。
  • On Answer 仍然负责最终结果、指标、工具调用以及结束时的 UI 状态。
  • On Error 中恢复发送按钮，并把可读错误显示出来。

按现象排错

现象首先检查
没有回答事件是否在 Ask 前绑定 On Answer；QuickChat 引用是否仍存活；同时查看 On Error 与运行时诊断。
每一轮都忘记前文Create Quick Chat 应只执行一次，不应每条消息执行一次；确认没有调用 Reset 或 Close。
返回字符串像一串 ID这是正确的 Request ID；回答在 On Answer → Result.Text。
第二次 Ask 被拒绝检查 Is Busy。同一个 QuickChat 不应重叠存在多个未完成请求。
编辑器可用，打包后失败确认模型存在于打包运行时实际路径，并打开 Runtime 返回的诊断目录。
