LMLiteRT-LM Unreal
插件总览 快速单对话 多对话 全部体系 C++ English

本地大模型 · 蓝图 + C++ · Win64 + Android

先让一个对话跑起来，再扩展成拥有独立记忆的 AI 世界。

LiteRT-LM Unreal 是一个按使用场景组织的本地 AI 插件。你可以从自动管理的单对话开始，再进入多 Agent、记忆、工具、MCP、原生 C++、诊断和打包；底层运行时无需反复删除和重做。

做出第一个对话 先选正确的 API
先记住这个模型：插件在进程内维护一个共享的 GPU 模型和串行推理队列；每个 Quick Chat 或 Agent 都有独立对话和记忆。“单对话”只是易用的兼容外观，并不是全局唯一会话。

按你正在做的东西选择

开始之前，不需要先读完全部 API

让 AI 对象的生命周期与游戏对象一致。教程先给出最小可用接口；复杂能力仍然完整保留在底层。

1

一个聊天框或助手

使用 Quick Chat

它会自动创建并持有一个普通 Agent。只绑定一次回答事件，然后调用 Ask Once 或 Ask Streaming。
N

多个 NPC、玩家或身份

每个身份一个 Agent

提示词、工具和记忆彼此独立；运行时与模型共享，因此不会为每个角色各加载一份模型。
A

AI 就属于某个 Actor

使用 LiteRT-LM Component

组件在 BeginPlay 创建一个 Agent，并把对话、记忆和工具事件直接暴露给所属 Actor。
M

外部工具或 MCP 路由

使用 MCP Gateway

固定工具结构，把调用路由到外部系统，提交结果后在同一段对话中继续推理。
C++

玩法代码或其他插件

优先使用 UObject API

C++ 同样可以使用 Quick Chat、Agent、Runtime 和 Gateway；只有确实需要更低层 ABI 时才进入 Native SDK。
→

发布到 Win64 或 Android

模型交付 + 诊断 + 打包

先决定模型如何到达设备，验证模型路径，再在目标设备检查运行时状态和诊断日志。

推荐顺序

符合人类习惯的学习路径

15 分钟

1. 先看到一条回答

设置模型路径，只创建一次 Quick Chat，绑定 On Answer，把最终文本打印出来。

下一步

2. 接入自己的 UI

按钮发送消息，保存对象引用，选择流式或整段输出，并处理忙碌与错误状态。

玩法

3. 拆成多个角色

每个身份创建一个 Agent；私密信息只发给对应角色，真实公共事件写入所有相关记忆。

发布

4. 增加工具并打包

加入结构化工具调用，按需接入 MCP，开启诊断，完成模型交付与真机打包测试。
